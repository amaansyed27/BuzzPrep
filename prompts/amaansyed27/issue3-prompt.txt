Goal

Create the deterministic layer that converts:

candidate profile
        +
31-day curriculum
        ↓
personalized interview plan



This planner should decide what BuzzPrep should assess, before Issue #5 turns that plan into adaptive AI interview questions.

The planner itself should be structured and deterministic.

Do not use an LLM for core planning logic in this issue.

Candidate profiling

Read the supplied candidate schema and extract useful interview signals including:

candidate/member ID;
name;
job role;
years of experience;
education if useful;
cohort completion status;
completed/passed missions;
failed missions;
skipped missions;
attempts per mission;
first-try performance;
total completed missions;
commit/activity signals.

Important:

status: COMPLETED does not mean every mission passed.

Treat mission states separately:

passed
failed
skipped



Do not count failed/skipped topics as demonstrated completion.

Curriculum grounding

Use curriculum.json as the source of truth.

For each curriculum day, preserve useful information such as:

day number;
module;
title;
learning objectives;
tools;
activity/type if relevant.

Do not invent curriculum concepts that are not present in the supplied file.

Interview planner

Generate a structured personalized interview plan.

The plan must guarantee that BuzzPrep can satisfy the hackathon requirement:

minimum 8 questions
across minimum 4 curriculum days



The planner should select at least 4 candidate-appropriate curriculum days.

It should not simply select the first four passed missions.

Use candidate signals to create a balanced plan.

Consider:

breadth across modules;
strong areas;
weaker areas;
missions requiring multiple attempts;
role/seniority;
progression through the cohort;
avoiding excessive concentration on one module.
Sparse candidates

The supplied candidates include profiles with very few passed days.

The implementation must handle these correctly.

For example, some candidates may have exactly four passed curriculum days.

The planner must still be able to create a valid 4-day interview plan.

Do not assume every candidate has completed advanced RAG/agent/MCP topics.

Failed/skipped topics

Failed or skipped topics may influence the plan, but distinguish them from completed material.

Recommended behavior:

passed → normal assessment candidate;
multiple attempts → possible deeper diagnostic/probe;
failed → optional diagnostic area if appropriate;
skipped → do not pretend the candidate completed it.

If skipped/failed material is included, explicitly mark its intent as something like:

diagnostic
exploratory
gap_check



rather than normal completed-topic assessment.

Difficulty

Generate a deterministic difficulty estimate for each planned curriculum area.

A simple scale is sufficient:

introductory
standard
advanced



or an equivalent structured enum.

Difficulty may consider:

candidate experience;
attempts;
first-try success;
mission completion;
role;
overall cohort performance.

Keep the rules understandable and testable.

Avoid opaque scoring formulas unless they add real value.

Interaction types

Use our curriculum-wide interactive BuzzPrep model.

Each planned area should include suitable interaction type(s), for example:

system_canvas
configuration_lab
data_workbench
prompt_schema_editor
code_config_repair
logs_metrics_explorer
test_evaluation_runner
incident_simulator
architecture_critique



Use docs/curriculum-interactions.md as guidance.

Do not hard-code BuzzPrep as a RAG/node-canvas product.
