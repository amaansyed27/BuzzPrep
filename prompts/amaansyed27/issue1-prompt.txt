Implementation

POST /api/interview now distinguishes start requests from conversation turns and persists the session across requests. It handles malformed requests, duplicate IDs, unknown IDs, and completed sessions with structured errors.

The route contains no database/business logic. Responsibilities are split across API, schemas, services, persistence models, and DB configuration.

Database

Two SQLAlchemy tables:

interview_sessions — candidate JSON, status, question/turn counts, curriculum coverage, current topic/day, challenge state, workspace snapshot, structured scores, completion state, timestamps.
interview_turns — ordered candidate/interviewer transcript with optional structured payload/evidence.

Local default is SQLite. DATABASE_URL can switch the same layer to PostgreSQL/Neon; psycopg 3 support was added.
